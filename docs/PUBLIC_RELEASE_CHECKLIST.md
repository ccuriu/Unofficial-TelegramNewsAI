## 2. Сессия и авторизация

- [x] Одновременный обычный запуск двух копий в одной Windows-сессии блокируется named mutex.
- [x] Существующая установка не начинает новую авторизацию автоматически, если пропал `telegram_session.session`.
- [x] Если сохранённая сессия перестала быть авторизованной, программа останавливается вместо скрытого запроса нового кода.
- [x] Явная команда `T` позволяет пользователю после подтверждения пересоздать только Telegram-сессию, не удаляя credentials, базу и список каналов.
- [x] Любой FloodWait виден приложению и прекращает текущий сетевой этап.
- [x] Ошибки, похожие на ограничение/отзыв сессии, не ретраятся вслепую.
- [x] Обычный дайджест сначала использует локальный entity-cache и не вызывает полный `get_dialogs(limit=None)` без необходимости.

## 5. Sponsored Messages

- [x] Исследование применимости требования Telegram API Terms о Sponsored Messages к текущей архитектуре завершено.
- [x] Основание зафиксировано: Unofficial TelegramNewsAI пакетно получает обычную историю выбранных каналов через `messages.getHistory` / Telethon `iter_messages` для локального хранения, поиска и экспорта и не предоставляет штатный интерфейс чтения Telegram-каналов или ленту сообщений. Sponsored Messages запрашиваются отдельным API-механизмом и в обычную историю сообщений не входят.
- [x] Для текущей архитектуры получение, хранение, экспорт и отображение Sponsored Messages не добавляются; изменений кода по этому вопросу не требуется.
- [x] Повторная проверка обязательна до публичного релиза встроенного просмотра Telegram-контента/ленты или при ином существенном изменении архитектуры в сторону полноценного Telegram-клиента.
