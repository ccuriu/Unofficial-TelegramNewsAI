# Безопасность и конфиденциальность

Unofficial TelegramNewsAI работает локально и использует пользовательские Telegram API credentials и Telegram-сессию. API Hash и файл сессии следует считать чувствительными данными.

## Telegram API и защитный профиль

В проведённых к настоящему моменту рабочих тестах Unofficial TelegramNewsAI не наблюдались ограничения аккаунта, потеря Telegram-сессии или повторная авторизация при обычном сценарии использования.

Telegram при этом отдельно предупреждает о дополнительном антиспам-контроле для аккаунтов, использующих неофициальные API-клиенты, а точные критерии и универсальные лимиты не публикуются. Это общее предупреждение платформы, а не указание на проблему именно этой программы. Проект учитывает его при проектировании сетевого поведения и при тестировании разных нагрузок.

В 5.4.13 Testing используется защитный профиль:

- `Telethon.flood_sleep_threshold = 0`: FloodWait не скрывается внутри библиотеки;
- первый обнаруженный `FloodWait` останавливает текущий сетевой этап без автоматического повторения нагрузки;
- ошибки, похожие на ограничение аккаунта, отзыв/истечение сессии или потерю авторизации, также останавливают сетевой этап вместо повторных запросов;
- обычный запуск сначала восстанавливает выбранные каналы из локального entity-cache Telethon и не запрашивает полный список диалогов без необходимости;
- если в уже настроенной установке отсутствует `telegram_session.session` или сохранённая сессия перестала быть авторизованной, автоматическая повторная авторизация не начинается; пользователь может явно пересоздать сессию командой `T`;
- одновременно запустить две обычные копии программы в одной Windows-сессии нельзя: используется системный named mutex;
- запросы истории идут последовательно; базовый профиль 5.4.13 использует `wait_time=0.5` для последовательных запросов большой истории и межканальную паузу 0,25 с, увеличиваемую до 0,5 с только для списков свыше 100 каналов.

Задача этих мер — не обход ограничений Telegram, а предсказуемая работа клиента, минимизация лишних запросов и корректная остановка при серверном сигнале. Сетевой профиль 5.4.13 быстрее 5.4.12, поэтому его реальные испытания учитываются отдельно.

Официальные сведения: [Telegram API](https://core.telegram.org/api/obtaining_api_id), [RPC errors / FLOOD_WAIT](https://core.telegram.org/api/errors), [Telethon FAQ](https://docs.telethon.dev/en/stable/quick-references/faq.html).

## Telegram Content Licensing и AI/ML

Программа сама не загружает собранный Telegram-контент во внешние AI/ML-сервисы. В 5.4.13 Testing локальный поиск работает через SQLite FTS5/LIKE без ML/embedding-модели.

Структурированный JSON и `recommended_digest_request` специально подготовлены для пользовательского анализа в выбранном ИИ-ассистенте, например ChatGPT. Передача файла выполняется только самим пользователем; автоматического вызова модели, обучения модели или фоновой отправки контента программа не выполняет. Для внешнего использования содержимого пользователь самостоятельно учитывает применимые правила Telegram, права авторов и условия выбранного сервиса.

Официальные правила: [Telegram API Terms](https://core.telegram.org/api/terms), [Content Licensing](https://telegram.org/tos/content-licensing).

## Публичный релиз

Публичное распространение остаётся приостановленным до завершения тестов API и проверки вопросов соответствия текущим правилам Telegram.

В пользовательском интерфейсе и новых сборках используется название **Unofficial TelegramNewsAI**, поскольку Telegram API Terms ограничивают использование слова “Telegram” в названии стороннего приложения без префикса “Unofficial”.

### Sponsored Messages

Текущая версия пакетно синхронизирует обычную историю выбранных каналов через Telethon (`messages.getHistory` / `iter_messages`) для локального хранения, поиска и JSON-экспорта и не предоставляет штатный интерфейс чтения Telegram-каналов или ленту сообщений. Sponsored Messages запрашиваются отдельным API-механизмом и не входят в обычную историю сообщений, поэтому текущая архитектура их не запрашивает, не сохраняет и не отображает.

Этот вывод относится к текущей архитектуре и не трактуется как специальное исключение из Telegram API Terms. Если в проекте появится встроенный просмотр Telegram-контента/лента сообщений или функциональность существенно приблизится к полноценному Telegram-клиенту, применимость требований Sponsored Messages должна быть проверена заново до публичного релиза такого изменения.

Официальные источники: [Telegram API Terms](https://core.telegram.org/api/terms), [Sponsored Messages](https://core.telegram.org/api/sponsored-messages).

## Что нельзя публиковать

Не прикладывайте к Issue, Pull Request, обсуждению или публичному сообщению:

- `credentials.bin` и `credentials.unreadable-*.bin`;
- любые `*.session` и `*.session-journal`;
- Telegram API ID, API Hash, код подтверждения и номер телефона;
- `news.db` и `news.db-*`;
- `selected_channels.json` и `settings_free.json`;
- логи и содержимое папок `Дайджесты` и `Резервные_копии`;
- cookies, токены, приватные URL и необработанные снимки экрана с личными данными.

Эти пути исключены через `.gitignore`, однако перед публикацией вложений их всё равно нужно проверять вручную.

## Сообщение об уязвимости

Если проблема связана с утечкой Telegram-сессии, учётных данных или выполнением произвольного кода, не публикуйте секреты в открытом Issue. Создайте минимальное описание без чувствительных значений и попросите сопровождающего предоставить безопасный канал связи.

Для обычных ошибок используйте шаблон Issue. В логах оставляйте только минимальный фрагмент и предварительно удаляйте личные данные.

## Если секрет уже опубликован

1. Считайте опубликованный API Hash, токен или файл сессии скомпрометированным.
2. Завершите затронутую Telegram-сессию через список активных устройств Telegram и авторизуйтесь заново.
3. Отзовите или замените опубликованные токены и другие credentials там, где это возможно.
4. Удалите публичное вложение или сообщение.
5. Если секрет попал в Git, помните: удаления файла новым коммитом недостаточно. До открытия репозитория нужно переписать историю, удалить секрет из всех refs и проверить клоны, форки, кэши CI и Release assets.

Не вставляйте скомпрометированное значение в Issue даже в замаскированном виде. Для идентификации достаточно типа секрета, пути и SHA коммита.

## Поддерживаемая версия

Исправления безопасности в первую очередь применяются к последней версии в ветке `main`.
