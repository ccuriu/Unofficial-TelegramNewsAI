# Безопасность и конфиденциальность

Unofficial TelegramNewsAI — локальная неофициальная Windows-утилита. Она использует пользовательские Telegram API credentials и Telegram-сессию; API Hash и файл сессии являются чувствительными данными.

## Защитный профиль Telegram API

В 5.5.0 Stable:

- `Telethon.flood_sleep_threshold = 0`: FloodWait не скрывается внутри библиотеки;
- первый FloodWait останавливает текущий сетевой этап;
- PEER_FLOOD, отзыв/потеря авторизации, frozen/banned и сходные account/session-level сигналы не ретраятся вслепую;
- скрытая повторная авторизация запрещена; восстановление сессии выполняется только явной командой `T`;
- запросы истории идут последовательно, без массового параллелизма;
- обычный запуск сначала использует локальный entity-cache;
- две обычные копии программы в одной Windows-сессии блокируются системным named mutex;
- продуктовый hard limit — 50 выбранных источников;
- локальный `API_SAFETY_SUMMARY` не содержит API Hash, auth keys, кодов подтверждения или содержимого session-файла.

Реальная приёмка режима 50 источников прошла без наблюдавшихся FloodWait, потери сессии или повторной авторизации. Это результат конкретных тестов, а не гарантия Telegram API.

## Локальные данные и внешняя обработка

Программа сама не загружает собранный контент во внешние AI/ML-сервисы, не содержит встроенного AI API и не выполняет обучение или дообучение моделей. Поиск выполняется локально через SQLite FTS5/LIKE.

Экспортированные JSON/Markdown-файлы остаются локальными до тех пор, пока пользователь сам не решит открыть или передать их другому инструменту. Условия такого внешнего сервиса применяются отдельно.

## Telegram Terms и Content Licensing

Проект не связан с Telegram FZ-LLC и использует пользовательское название **Unofficial TelegramNewsAI**. Публикация исходного кода не является заявлением о специальном исключении из Telegram API Terms или Content Licensing.

Текущая пакетная архитектура синхронизирует выбранные источники для локального хранения/поиска/экспорта и не является полноценным интерфейсом чтения Telegram-ленты. Она не запрашивает отдельный поток Sponsored Messages. Это зафиксированное свойство текущей версии, а не универсальное юридическое заключение. При переходе к встроенному reader UI, hosted-сервису, автоматической внешней обработке или иной новой продуктовой модели условия платформы должны быть перепроверены до релиза.

Официальные документы: [Telegram API Terms](https://core.telegram.org/api/terms), [Content Licensing](https://telegram.org/tos/content-licensing), [Sponsored Messages](https://core.telegram.org/api/sponsored-messages). Техническая фиксация исследования: [docs/TELEGRAM_API_TERMS_RESEARCH_2026-09-22.md](docs/TELEGRAM_API_TERMS_RESEARCH_2026-09-22.md).

## Хранение credentials

`credentials.bin` шифруется Windows DPAPI и привязан к профилю Windows. Telethon session-файл хранится локально и сам по себе является чувствительным credential. Не копируйте эти файлы в репозиторий, Issue, PR, чат или публичное хранилище.

## Безопасное обновление

`UPDATE.bat` / `update.ps1` и переносимый `TelegramNewsAI_Update.cmd` заменяют только программные файлы, перечисленные в `release_manifest.json`. Session, credentials, настройки, выбранные каналы, `news.db*`, дайджесты, логи, резервные копии, `.venv` и неизвестные локальные файлы не входят в whitelist.

Перед заменой управляемых файлов updater создаёт временную резервную копию; при ошибке программная часть откатывается. Критические пользовательские файлы сверяются до и после обновления. Updater не подключается к Telegram и не выполняет авторизацию.

## Что нельзя публиковать

Не прикладывайте к Issue, Pull Request, Discussions, Actions artifact или публичному сообщению:

- `credentials.bin` и `credentials.unreadable-*.bin`;
- любые `*.session` и `*.session-journal`;
- Telegram API ID, API Hash, код подтверждения и номер телефона;
- `news.db` и `news.db-*`;
- `selected_channels.json` и `settings_free.json`;
- логи и содержимое `Дайджесты` / `Резервные_копии`;
- cookies, токены, приватные URL и скриншоты с личными данными.

Эти пути исключаются `.gitignore` и дополнительно проверяются CI, но перед публикацией вложений всё равно нужна ручная проверка.

## Сообщение об уязвимости

Не публикуйте секрет в открытом Issue. Для обычной ошибки оставляйте минимальный безопасный фрагмент лога. Если проблема связана с утечкой session/credentials или выполнением произвольного кода, опишите тип проблемы без чувствительного значения и запросите безопасный канал связи.

## Если секрет уже опубликован

1. Считайте значение скомпрометированным.
2. Завершите затронутую Telegram-сессию в списке активных устройств и создайте новую.
3. Замените опубликованные токены/credentials там, где это возможно.
4. Удалите публичное вложение.
5. Если секрет попал в Git-историю, обычного удаления новым коммитом недостаточно: историю и все refs нужно очистить до публичного открытия.

## Поддерживаемая версия

Исправления безопасности в первую очередь применяются к последней версии ветки `main`.
