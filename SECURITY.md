# Безопасность и конфиденциальность

Unofficial Telegram News Digest работает локально и использует пользовательские Telegram API credentials и Telegram-сессию. API Hash и файл сессии следует считать чувствительными данными.

## Риск ограничений Telegram API

Telegram предупреждает, что аккаунты, входящие через неофициальные API-клиенты, автоматически находятся под дополнительным наблюдением антиспам-системы. Точные критерии ограничений и универсальные безопасные лимиты не публикуются и могут меняться.

Программа не отправляет сообщения, реакции или публикации, не подписывает аккаунт на каналы автоматически и читает выбранные каналы последовательно через Telethon. Это уменьшает лишнюю активность, но не позволяет гарантировать отсутствие временного ограничения или блокировки конкретного аккаунта.

В 5.4.13 Testing используется защитный профиль:

- `Telethon.flood_sleep_threshold = 0`: библиотека не пережидает FloodWait скрыто от приложения;
- первый обнаруженный `FloodWait` останавливает текущий сетевой этап без автоматического повтора;
- ошибки, похожие на ограничение аккаунта, отзыв/истечение сессии или потерю авторизации, также останавливают сетевой этап вместо повторных запросов;
- обычный запуск сначала восстанавливает выбранные каналы из локального entity-cache Telethon и не запрашивает полный список диалогов без необходимости;
- если в уже настроенной установке отсутствует `telegram_session.session` или сохранённая сессия перестала быть авторизованной, автоматическая повторная авторизация не начинается;
- одновременно запустить две обычные копии программы в одной Windows-сессии нельзя: используется системный named mutex;
- запросы истории идут последовательно с явным `wait_time` и межканальной паузой.

Если потеря доступа к аккаунту критична, учитывайте этот риск до первой авторизации. Новый или виртуальный номер не следует считать автоматически более безопасным.

Официальные сведения: [Telegram API](https://core.telegram.org/api/obtaining_api_id), [RPC errors / FLOOD_WAIT](https://core.telegram.org/api/errors), [Telethon FAQ](https://docs.telethon.dev/en/stable/quick-references/faq.html).

## Telegram Content Licensing и AI/ML

В 5.4.13 Testing AI/ML-функциональность исключена из публичного продукта по архитектуре:

- программа не отправляет Telegram-контент внешним AI/ML-сервисам;
- ML/embedding-поиск по сообщениям отключён;
- структурированные экспорты не содержат встроенных AI/ML-промптов или инструкций для передачи в модели;
- поиск и группировка выполняются локальными детерминированными алгоритмами и SQLite FTS5/LIKE.

Это означает, что сама программа не использует данные Telegram для обучения, дообучения, валидации, бенчмаркинга, разработки, улучшения или развёртывания AI/ML. Пользовательское применение экспортированных данных вне программы не становится автоматически разрешённым: на него по-прежнему распространяются Telegram Content Licensing, права авторов и применимое законодательство.

Официальные правила: [Telegram API Terms](https://core.telegram.org/api/terms), [Content Licensing](https://telegram.org/tos/content-licensing).

## Публичный релиз

Публичное распространение остаётся приостановленным до завершения тестов API и проверки вопросов соответствия текущим правилам Telegram.

В пользовательском интерфейсе и новых сборках используется название **Unofficial Telegram News Digest**, поскольку Telegram API Terms ограничивают использование слова “Telegram” в названии стороннего приложения без префикса “Unofficial”.

API Terms содержат прямое требование поддержки официальных Sponsored Messages для сторонних приложений, позволяющих получать содержимое Telegram-каналов. Для этого проекта вопрос считается применимым и остаётся отдельным блокером публичного релиза до корректной реализации или письменного разъяснения Telegram.

## Что нельзя публиковать

Не прикладывайте к Issue, Pull Request, обсуждению или публичному сообщению:

- `credentials.bin` и `credentials.unreadable-*.bin`;
- любые `*.session` и `*.session-journal`;
- Telegram API ID, API Hash, код подтверждения и номер телефона;
- `news.db` и `news.db-*`;
- `selected_channels.json` и `settings_free.json`;
- логи и содержимое папок `Дайджесты` и `Резервные_копии`;
- cookies, токены, приватные URL и необработанные снимки экрана с личными данными.

Эти пути исключены через `.gitignore`, однако перед публикацией вложений их всё равно нужно проверять вручную.

## Сообщение об уязвимости

Если проблема связана с утечкой Telegram-сессии, учётных данных или выполнением произвольного кода, не публикуйте секреты в открытом Issue. Создайте минимальное описание без чувствительных значений и попросите сопровождающего предоставить безопасный канал связи.

Для обычных ошибок используйте шаблон Issue. В логах оставляйте только минимальный фрагмент и предварительно удаляйте личные данные.

## Если секрет уже опубликован

1. Считайте опубликованный API Hash, токен или файл сессии скомпрометированным.
2. Завершите затронутую Telegram-сессию через список активных устройств Telegram и авторизуйтесь заново.
3. Отзовите или замените опубликованные токены и другие credentials там, где это возможно.
4. Удалите публичное вложение или сообщение.
5. Если секрет попал в Git, помните: удаления файла новым коммитом недостаточно. До открытия репозитория нужно переписать историю, удалить секрет из всех refs и проверить клоны, форки, кэши CI и Release assets.

Не вставляйте скомпрометированное значение в Issue даже в замаскированном виде. Для идентификации достаточно типа секрета, пути и SHA коммита.

## Поддерживаемая версия

Исправления безопасности в первую очередь применяются к последней версии в ветке `main`.
