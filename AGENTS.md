# AGENTS.md — Unofficial-TelegramNewsAI: правила работы исполнителей


## Обязательный межпроектный канон администраторов URIU (решение владельца 31.10.2026)

**Для текущих и будущих MAIN ADMIN, преемников, веб-чатов, Codex и локальных исполнителей.** Администратор обязан: **(1)** выдавать список задач, карту исполнителей/ролей, отдельные точные TXT и общий пакет при параллельных заданиях; **(2)** разрешать и требовать самостоятельного исправления сопутствующих ошибок собственной области до функционального результата в одном CLAIM, а при чужом блокере передавать минимальный точный патч владельцу без остановки независимой работы; **(3)** при исправном авторизованном URIU Bridge назначать обычные чаты ChatGPT через плагин на разработку, правку кода, тестирование и исправления **наравне с Codex**, используя Codex при действительном преимуществе, а не как обязательный посредник. Чужие исключительные права, реальный выпуск, owner GO, безопасность и запрет повторов UNKNOWN сохраняются. **При создании любого нового проекта перенести эту ссылку в его AGENTS.md.**

[Полный обязательный канон администрирования](https://github.com/ccuriu/uriu-control-bridge/blob/main/docs/CROSS_PROJECT_ADMIN_EXECUTION_CANON.md).

## ПРАВИЛО ВЛАДЕЛЬЦА ДЛЯ ВСЕХ ПРОЕКТОВ URIU — автономное исправление блокеров

**Постоянный канон (2026-10-30).** Исполнитель не прекращает работу при каждой обычной ошибке: поставленная задача уже включает самостоятельную диагностику, исправление проблем в своих исходниках, тестах, фикстурах, адаптерах и сборке, повторную проверку и доведение до полезного проверенного результата. Одна задача/CLAIM и одна рабочая ветка — исправляем найденные по пути зависимые дефекты без нового Issue на одну строку. Это правило обязательно для веб-чатов, Codex, локальных агентов, MAIN ADMIN и QA.

Если блокер находится в чужих эксклюзивных файлах: подготовить точный минимальный patch/handoff, продолжить независимую часть и менять чужой код только после передачи права записи. Реальные опасные действия, производство, merge/release, секреты, ACL/SID/source attestation, лицензии, физические устройства, безопасность и принятый/UNKNOWN request без повторного запуска остаются под действующими ограничениями проекта. RED-результат — повод исправить проблему; подменять native/installed/live проверки фикстурами нельзя. Остановиться допустимо только по доказанному жёсткому препятствию с точными данными и одним следующим действием.

Это новое решение владельца имеет приоритет над более ранним правилом «STOP после одной обычной диагностики» **только для сопутствующих исправляемых ошибок в своей области**. Все действующие профильные запреты и исключительное владение релизом сохраняются.

## Правила конкретного проекта

Прежде чем писать код, сверить README, текущее целевое Issue, действующие project docs и занятые CLAIM/ветки. Обычная самостоятельная правка блокеров разрешена только в собственной подсистеме; крупные архитектурные решения, установка, релиз, доступы и опасные действия — по специальным правилам этого репозитория и решению владельца. Подтверждать точные commit/SHA, тесты и фактический статус SOURCE/NATIVE/INSTALLED/LIVE; не повторять неизвестные запросы и не подменять полезную работу отчётами.
